# Air75v3灯光助手

英文名为 **Air75 V3 RGB Lab**，当前 Mac 版为 **v1.0.11**。安装包和应用内名称仍为 **NuPhyLab**。

[English-first bilingual overview / 英文优先双语主页](README.md) · [Downloads / 下载](README.md#downloads--下载) · [Documentation / 文档目录](docs/README.md)

本文件保留详细中文使用指南。最新 Mac 开发版为 [v1.0.11](https://github.com/bohu8264/NuPhyLab/releases/tag/v1.0.11)；单独提供的 Windows 包为 [Preview 5](https://github.com/bohu8264/NuPhyLab/releases/tag/v1.0.0-windows-preview.5)。两端功能和验证范围不同，请勿将 Mac 验收记录当作 Windows 验收。分享项目可使用固定的[项目主页](https://github.com/bohu8264/NuPhyLab)。

为 NuPhy Air75 V3 创作灯光的本地 Mac 应用。用键盘画图案、播放动画、玩贪吃蛇、打地鼠、记忆灯序和双人乒乓球，也可以把 F1–F6 用作任务状态灯：可以选择 **Codex** 或 **Claude Code** 作为状态来源。

应用由原生 macOS 窗口、菜单栏常驻程序、可视化编辑器和用户态 HID 控制组成。无需内核驱动，不刷键盘固件。Codex 功能键适配包含临时系统映射及已确认的原厂 Mac F4 单键备份与恢复，关闭模式后还原。作品和设置保存在这台 Mac，动画运行时由电脑向键盘发送 RGB 帧。

## 打开应用

打包后的应用位于 **`release/NuPhyLab.app`**，双击打开即可。也可在项目根目录执行：

```sh
open "release/NuPhyLab.app"
```

应用包自带 Node.js 运行时，运行打包应用不需要另外安装 Node。当前构建使用这台 Mac 的处理器架构，并非 Universal 通用二进制。

首次使用：

1. 用数据线连接 Air75 V3，并使用有线模式。关闭 NuPhyIO 和其他正在控制键盘灯光的程序。
2. 打开 NuPhyLab 后插入键盘即可自动识别，不需要输入序列号或手动配对。未连接时显示「等待插入键盘」，之后每约 2 秒自动检查连接；「设备」页默认开启「插线后自动连接」。
3. 灯效控制、额度读取和任务跳转可直接使用。发送 Codex 系统组合键的操作需要 NuPhyLab 的「辅助功能」权限；未授权时界面会禁用并标注。输入监控仅针对可选原生按键监听，当前灯效连接不依赖它。
4. 回到「创作台」，先选择图案或画笔颜色，再点击「播放到键盘」。建议从较低亮度开始。

**蓝牙快捷控制：** 在 macOS 中连接 Air75 V3 蓝牙后，NuPhyLab 会自动识别。开启「Codex 模式」，已有的任务键（默认 F1–F6）、命令键（默认 F7–F12）和自定义绑定可继续使用，无需 USB 灯光连接。任务与额度仍可在软件里查看。「键盘适配」兼容标准 F1–F12 和发送 F13–F24 的扩展功能键模式，仅对这把键盘做临时系统转换，关闭后恢复。若功能键仍发送亮度或音量，使用标准 F 键组合，或在「更改」中绑定其他按键。

蓝牙模式不提供软件控制的 RGB 状态灯、灯效播放、按键灯效、灯光游戏、灯光计时或固件检查。作品仍可离线编辑、预览、保存和导入导出，原灯光设置不会清除；切回有线后继续使用。蓝牙配对由 macOS 管理，NuPhyLab 的「检查连接」只重新识别设备。实际验证范围见 [蓝牙支持说明](docs/BLUETOOTH.md)。

如果提示先开启键盘灯光，请在实体键盘上按一次 **Fn＋↑**，再点击播放。板载灯光总开关关闭时，软件无法直接接管灯光。

连接成功后会在后台查询 NuPhy 官方正式固件。发现旧版本时，各页面会显示简洁的更新提醒；设备页提供「检查更新」和「前往官方更新」。点击前往更新会先恢复原灯效并释放 USB 连接，再打开 NuPhyIO；Mac 优先使用已安装的 Chrome 或 Edge。完成官方更新后回到 NuPhyLab，点击「连接键盘」重新读取版本。应用不会自行刷写固件。

官方版本信息缓存 6 小时，可手动重新检查；联网失败显示无法检查或上次版本，已兼容的灯效仍可使用。v1.0.2 新增 1.0.23.6 的 22 字节灯光协议适配；同一 S4 1.x.x.6 协议系列后续更新按设备结构、状态和 RGB 回读校验，不再限定一个固件版本。协议发生变化时停止写入并提示更新软件。升级前的恢复记录会保留归档，不会强行写进新固件。v1.0.3 已在 1.0.23.6 真机完成逐键颜色回读和恢复验证，并修复软件运行中升级固件后的重连问题。新固件会缩放逐键输出亮度，校验已按实际渲染值适配。详见 [兼容性与验证记录](docs/FIRMWARE_COMPATIBILITY_20261015.md)。

v1.0.10 修复部分 1.0.23.6 键盘被误判为协议变化的问题：保留扩展灯效原始参数，按官方 D6 分段写入，并验证完整恢复。详见[换键盘后的真机验证](docs/RELEASE_QA_1.0.10.md)。

v1.0.11 开启 Codex 灯光时会停止其他灯效、游戏和声音采集，关闭非任务灯位与侧灯；修复 1.0.23.6 主灯颜色量化造成的恢复失败，断开连接不再被恢复错误卡住。已完成官网回退、应用提示更新、官网升级及升级后真机回归，详见[本版验证记录](docs/RELEASE_QA_1.0.11.md)。

分享给 Mac 用户时使用 [NuPhyLab-macOS-arm64.zip](https://github.com/bohu8264/NuPhyLab/releases/download/v1.0.11/NuPhyLab-macOS-arm64.zip)。此包适用于 Apple Silicon Mac、macOS 13.5 及以上、Air75 V3 ANSI；自带运行时，不含你的作品库或账户数据。首次打开仍遵循 macOS 的系统要求。Intel Mac、ISO/JIS 布局没有对应的已验证 Mac 安装包。Windows 预览版独立发布，要求和限制见 [Windows guide / Windows 指南](README.Windows.md)。

设备页的权限状态来自 macOS 只读查询。点击输入监控或辅助功能旁的「允许」，会打开对应的系统设置页面；需在系统设置中为 NuPhyLab 开启权限，按钮本身不会自动授权，也不会调用权限请求 API 弹出授权提示。返回 NuPhyLab 的设备页后会自动刷新状态，打开设置成功不等于权限已允许。

若权限列表中没有 NuPhyLab，可用列表下方的「＋」添加应用。当前本机的跳转与界面验证范围见 [权限入口验收记录](docs/PERMISSIONS_QA.md)。

权限页跳转使用 macOS 未公开的设置深链，不保证所有 macOS 版本都能定位到同一页面；若未打开对应页面，请进入「系统设置 → 隐私与安全性 → 输入监控 / 辅助功能」。这是 [Apple 未公开 URL scheme 的兼容性限制](https://developer.apple.com/forums/thread/761314)。源码运行时，权限可能归属于启动程序的终端，而不是打包后的 NuPhyLab。

从 **v1.0.1** 起，对外发布包使用 **Shenzhen NuPhy Technology Co., Ltd. 的 Developer ID**，启用 Hardened Runtime 与安全时间戳，完成 Apple 公证并附带 staple 票据。正常情况下无需在系统设置里点「仍要打开」；首次联网下载提示和功能权限提示仍可能出现。当前构建为 Apple Silicon（arm64）。发布机的 Gatekeeper assessments 原本关闭，尚需在另一台默认安全设置开启的 Mac 上完成首次安装验证，不能把本机检查等同于该验证。

从旧版开发签名升级会改变签名团队，可能需要重新授予可选的辅助功能或输入监控权限，作品数据目录保持不变。公司分发流程见 [macOS distribution](docs/MACOS_DISTRIBUTION.md)。

## 界面与窗口

创作功能统一位于左侧「创作台」下方。键盘预览在上，当前功能的参数在下：绘制页集中显示颜色、键盘亮度和快速图案；动画、按键触发和游戏各自显示对应控件。

默认内容区为 1100×700，窗口边缘可拖动调整，最小内容区为 720×520。小窗口会纵向排列参数并允许滚动。界面截图和对照记录见 `docs/design/refresh-2026-09/`，本轮验证见 `docs/UI_REFRESH_QA.md`。

## 语言与灯光时间

左下角「语言 / Language」可在简体中文和 English 之间切换，立即生效并保存在本机。导航、创作控件、预设、游戏状态、设备说明、弹窗以及应用菜单均跟随切换；已有作品名和任务名保留原文。系统设置和系统文件选择器仍使用 macOS 的语言。

「设备 → 灯光时间」统一控制主灯、侧灯和 Codex 状态灯：

- **每次亮灯时长**：播放、手动唤醒或开启 Codex / Claude Code 模式后重新计时，到时熄灯；点击「唤醒灯光」或重新播放再开始。开启任务灯光不会沿用之前作品剩余的亮灯时间。
- **空闲多久后休眠**：键盘、鼠标或应用长时间无操作时熄灯，恢复操作后自动唤醒。仅查询系统空闲计时，不记录输入内容；Codex 任务状态变化也视为活动。
- 可选择秒、分钟、小时，范围 1 秒至 24 小时；填 0 或点「不限」关闭对应计时。输入后回车或移开焦点保存。两项默认均为 1 小时；已有自定义设置保持不变。
- 休眠期间动画和游戏暂停推进，唤醒后继续；按键触发仍由已配置的按键唤醒并播放闪烁。

「Codex → 状态灯」可设置六种状态颜色、亮度、控制任务呼吸和命令键状态流光；全部亮灯与休眠时间统一在设备页设置。旧版 Codex 的独立息灯和提示时长不再生效。非运行任务的命令键颜色保持到选择或状态变化，并与整把键盘一起休眠。

在「状态颜色」点击色块，用色盘或十六进制值修改，再点击「应用颜色」。颜色保存到本机，任务灯、状态标记和命令键流光同步使用；可一键恢复默认颜色。启用 Codex 时，其绑定灯位使用这组状态色。

Codex 页的「灯光模式」可切换「多任务灯位」与「单任务全键盘」。后者让整把键盘的按键灯用同一种颜色显示一个任务的状态，沿用状态颜色、亮度和统一休眠设置。只有一个任务时自动跟随；多个任务时，可在「跟随任务」指定一个，也可选择自动并用任务键切换控制任务。指定的任务暂不可用时保持熄灯，不会自动改为别的任务。任务快捷键折叠保留，命令键仍可使用；单任务模式不叠加命令键流光，切回多任务后恢复原设置。v1.0.11 开启助手灯光会停止其他效果并独占灯光；主动开始其他效果会转移灯光控制权，任务状态仍继续读取，保存的原有图案保留。

In English: use the language selector at the bottom left. **Device → Lighting timers** sets **Light-on duration** and **Sleep after inactivity** for key lights, side lights, and Codex status lights together. Enter seconds, minutes or hours; 0 means no limit. Codex has no separate timeout. Settings persist across restarts.

## 图案与作品库

在「创作台 → 绘制」中：

- 「颜色应用到」默认是当前图案；选中按键后只修改选中位置，也可切换到「整把键盘」或「仅画笔」。开启实时预览时，换色会同步到键盘；播放动画时编辑图案会切换为静态预览。仅画笔模式用于逐键绘制不同颜色。
- 在连续色盘上拖动选色：绕圆盘改变色相，向圆心移动降低饱和度；下方「明暗」滑条调整所选颜色的深浅。色值可直接输入或复制，「键盘亮度」单独控制整体输出亮度。色盘支持方向键微调，按住 Shift 加大步幅。
- 用「画笔」点击或拖动键盘，为每个位置上色；同一颜色可以绘制整颗爱心，也可以逐键换色。
- 用「选择」同时选中多个位置，再统一修改颜色；「橡皮擦」将位置变为黑色。
- 可以使用爱心等预设，也可以清空画布后从头画；工具栏提供撤销和重做。
- 点击「保存作品」，输入名称。图案和动画设置会一起保存到本机作品库。

画布草稿与已保存作品分开。需要保留的修改请明确点击保存；关闭应用前不要把未保存的草稿当成已经入库。

「作品库」支持搜索、打开、重命名、删除，以及 JSON 导入、单个作品导出和导出全部。导入会生成新的作品 ID，不覆盖同名作品。当前最多保存 200 个作品。打包应用的导出文件写入 Mac 的「下载」目录，并带有 NuPhyLab 和时间戳前缀。

## 默认图案与灯效

在「作品库 → 默认预设」中选择「动态图形」或「氛围灯效」，也可从绘制页「更多图案与灯效」进入。12 个预设全部自带循环动效，支持按名称和描述搜索；「我的作品」单独展示已保存内容。

- 动态图形：一颗小心意（约 3.5 秒一次呼吸，保留原 19 键轮廓）、眨个眼、星光闪闪、月光轻漾、蝴蝶振翅、向右流光。
- 氛围灯效：薄荷呼吸、流星划过、蓝色涟漪、紫色星点、琥珀落雨、青绿扫描。

每张卡片上的「页面预览」只改变缩略图，一次预览一个灯效，不向键盘发送颜色。点击「使用灯效」进入动画页，再点击「播放到键盘」实际播放。所有预设均可修改并另存为独立作品，不覆盖默认预设或已有作品。空白画布统一从「新建作品」进入；不再展示菱形与旧蝴蝶结预设，个人已保存的旧作品保持原样。

十种逐帧动效共 344 帧，可逐帧改色、修改时长、复制或删除。速度 4 使用原始帧时长，速度 8 为两倍速度，速度 2 为一半速度；方向由每帧画面决定，因此逐帧模式不显示无效的方向按钮。爱心与薄荷呼吸使用连续明暗变化，可直接调色和调速。默认目录不包含彩虹效果。

页面直接显示 RGB 颜色，不再向暗色混入白色。实时绘制／播放时显示最后一次成功发送的 RGB 帧，包含键盘亮度和 Codex 灯位接管；未播放的草稿和作品缩略图显示作品原色。黑色表示灯关闭，画布仍显示未点亮的浅色键帽。屏幕和实体 LED 的发光材料不同，数字一致不等于经过光学校色。

## 声音律动

在「创作台 → 声音律动」选择系统声音或麦克风，再点击「开始律动」。现有 10 种效果：音量呼吸、频谱跳动、鼓点扩散、中心声浪、旋律波浪、音符落雨、节奏流星、星点闪动、心跳爱心、高低音对话。呼吸效果增强了重拍与弱拍的明暗对比；播放中可直接切换效果。颜色可选「单色 / 彩色」：单色用色盘自定义，彩色为十种效果加入多色渐变或频段配色；切换不会中断采集，并保留原单色设置。在「调整响应」中设置灵敏度和噪声门限。鼓点扩散、节奏流星和心跳爱心会检测原始频段的敲击变化；提高灵敏度可跟上更轻的鼓点，跳动过密时调低。系统声音需要 macOS 14.2 或以上，麦克风可选择内置或已连接的外置输入。

此功能需要 USB 有线连接。音频仅在本机即时分析，不保存或上传；按 macOS 提示授权后才能采集。统一休眠设置生效，停止、切换作品或退出会结束采集，重新打开软件不会自动采集。律动期间暂停 Codex 灯光覆盖，任务和命令快捷键仍可用。详细说明与验证范围见 [声音律动](docs/AUDIO_REACTIVE.md)。

## 动画与逐帧播放

在「创作台 → 动画」中，可以选择静态、移动、呼吸、波浪或逐帧效果。旧版彩虹作品和草稿按静态图案读取，保留原有键位颜色。

让爱心向右循环移动：

1. 在画布中画好爱心，或选用爱心预设。
2. 切换到「动画」，选择「移动」，方向设为「向右」。
3. 调整速度并打开「循环播放」。
4. 点击「播放到键盘」，满意后保存作品。

逐帧动画适合自己安排每一个画面：先绘图，点击「从画布添加一帧」；修改画布后继续添加。点击已有帧可编辑，再用「更新画面」写回该帧。可以复制或删除帧、设置每帧时长，再决定是否循环。每个作品最多 120 帧，每帧 80–10000 毫秒。

全局亮度由软件缩放 RGB 值。底层开启自定义模式时使用硬件亮度 100，以便精确显示软件给出的颜色；用户看到的亮度仍由应用滑块控制。画面不变时不会持续重复发送相同帧。

键盘行列并非完整的矩形像素网格，宽键与错位行会影响移动图案的轮廓。移动效果按已知物理位置寻找相邻灯位，不等同于高分辨率屏幕动画。

## 键盘游戏

四款游戏统一放在「创作台 → 游戏」中。先选择游戏和 1–10 的速度，再点击「开始游戏」。一次运行一款游戏；切换类型会结束当前局，再进入新游戏的准备状态。

| 游戏 | 规则与操作 |
| --- | --- |
| 贪吃蛇 | 用方向键或界面方向按钮移动。吃到珊瑚色食物后变长并加 1 分，碰到边界或身体结束，填满键盘获胜。六行全部 83 个已映射按键都可成为蛇或食物的位置。 |
| 打地鼠 | 26 个字母键中随机亮起一键，按下对应字母或点击键盘图即可命中并加 1 分。每局 30 秒，目标超时会换到下一键；界面分别统计命中、漏掉和错按，错按不加分。速度越高，单个目标停留越短。 |
| 记忆灯序 | 观察 A、S、D、F、J、K、L、; 的闪灯顺序，提示输入后按原顺序重复，也可以点击对应界面按键。每过一轮加 1 分，并增加一个灯序；每次输入等待上限为 10 秒，按错或超时结束，完成 20 轮获胜。速度控制示范闪灯时长。 |
| 双人乒乓球 | 左方用 W / S，右方用 ↑ / ↓，按住移动、松开停止，也可按住界面球拍按钮。两侧各有两键高的球拍，绿色代表左方，珊瑚色代表右方，浅色灯代表球。球上下反弹，漏接后对方加 1 分，约 0.9 秒后重新发球，先得 7 分获胜。速度控制球速。 |

四款游戏共用空格键暂停或继续，也可使用「暂停 / 继续」按钮。需要保持 NuPhyLab 的游戏页在前台；切换到其他应用、隐藏窗口或离开游戏页会自动暂停并释放按住的球拍方向，回来后手动继续。游戏不会在其他应用中拦截按键；在输入框中输入时也不会触发游戏操作。

游戏期间只点亮当前游戏对象：蛇和食物、地鼠目标、记忆提示或球拍与球。其余背景主键通道、保留通道 83 和 20 个侧灯通道保持黑色，Codex 任务状态叠加与额度侧灯暂停。可映射按键依据真实物理位置显示；宽空格仍只对应一颗灯，右上角原旋钮位置按用户要求显示装饰 Del 键帽，没有可玩灯位。贪吃蛇覆盖 83 个已映射按键，其他游戏按各自规则使用其中的位置，不能把 84 个主区逻辑通道都视作可玩按键。

失败后，全部 83 个可控按键灯闪红三次（每次亮 0.3 秒、暗 0.3 秒），之后熄灯等待；打地鼠计时结束、双人乒乓球整场分出胜负也使用这一提示，乒乓球单次丢分不会闪烁。贪吃蛇填满键盘和记忆灯序通关仍保留胜利画面。

一局结束后，按回车（Enter 或数字键盘回车）或点击「再来一局」开始新局，保留当前速度和最高纪录。闪红期间也可重开；长按回车不会连续重置。输入框内及其他应用中不会拦截回车。点击「结束」退出游戏控制并恢复进入游戏前的场景。每款游戏的最高纪录分别保存到本机：贪吃蛇记录吃到的食物数，打地鼠记录命中数，记忆灯序记录完成轮数，双人乒乓球记录单局双方总得分，同时单独显示双方比分。旧版贪吃蛇的最高分会保留为贪吃蛇纪录。

## Codex 任务与快捷控制

当前 Codex 集成只是部分实现。完整 Micro 功能、灯光预设、现有缺项及补齐验收基线见 [Codex Micro 功能核查](docs/CODEX_MICRO_AUDIT.md)；逐个动作见 [命令与键帽清单](docs/CODEX_MICRO_COMMANDS.md)。文档里的候选功能不代表已经接入。

在「Codex」页开启「Codex 模式」后，默认 F1–F6 显示六个槽位，直接按键或点击对应键帽即可打开任务。任务来源分为最近、固定、优先、自定义；固定模式读取本机固定任务，自定义模式保留空槽，重复选择会交换位置。固定项目内的任务与云端任务尚未合并。

| 状态 | RGB |
| --- | --- |
| 正在运行／思考 | `#304FFE` |
| 未读结果 | `#00FF4C` |
| 等待回答／已识别的批准请求 | `#FF6D00` |

| 无法确认 | `#858582` |

状态灯有独立的 0–100% 亮度，最终还受键盘总亮度影响；亮灯和休眠统一使用设备页的全键盘计时。打开任务会选中 NuPhyLab 的控制任务并显示呼吸；命令键状态流光可在工作中移动，非工作任务保持状态颜色，随全键盘一起休眠和唤醒。灯光位置跟随绑定按键。此控制任务不等于 Codex 当前前台任务。开启 Codex 灯光会停止其他模式并独占灯位；之后主动播放作品或开始游戏、触发、声音律动时，灯光交给新模式。返回 Codex 页可点击「启用 Codex 灯光」重新接管，保存的作品不会删除。

**一个开关控制功能键：** 开启「Codex 模式」时，已绑定的按键用于 Codex；关闭时解除接管并恢复这把键盘原先的功能，保留绑定供下次启用。USB 与蓝牙均兼容实体 F1–F12 发送 F13–F24 的扩展层；USB 按实际读取的键位适配，不写入键盘固件。点「更改」时暂停命令执行，但临时保持完整 F 区可录入（包括当前未绑定的 F 键）；保存或取消后恢复原模式。录入会话失联 15 秒后自动撤销临时适配。

**恢复键帽功能：** 若键盘自身 F 区已设置为 F13–F24，单纯撤销 Codex 映射不能恢复亮度、播放等功能。可在「Codex → 查看适配 → 适配说明 → 关闭模式后」选择「键帽上的原厂功能」。NuPhyLab 会在关闭 Codex 模式时，为完整扩展 F 区应用亮度减／加、Mission Control、搜索、听写、勿扰、上一曲、播放／暂停、下一曲、静音、音量减／加的顺序；开启后使用 Codex 绑定。此兼容层需要 NuPhyLab 保持运行，退出后恢复键盘自身配置，不改写固件或其他按键。USB 会核对当前 Mac 层与原厂层；普通 F 键、原厂层和不完整的自定义层不作猜测。蓝牙只转换对应扩展键，不影响标准 F 键。

**任务键默认 F1–F6，命令键默认 F7–F12，直接按下即可执行。** 每个键旁的「更改」会打开录入窗口：按下所需普通按键，松开保存；若新键已被任务或命令占用，会自动交换。设置保存到本机，重启保留。支持字母、数字、空格、方向键、编辑键和 F1–F12；Fn 与修饰键不作为独立快捷键。Del 可执行动作，但右上角没有独立可控 LED。绑定期间、NuPhyLab 输入控件编辑期间以及游戏、按键触发期间暂停快捷控制。关闭 Codex 控制会释放注册的键。原生应用通过 Carbon 注册全局按键，并用前台窗口事件补充；按住不重复执行。普通浏览器只在当前窗口接收按键。发送系统快捷键需要辅助功能权限；任务 ID 跳转无需此权限。Codex 中自定义键位及页面上下文可能改变命令执行结果。系统占用导致注册失败时，页面显示具体键位。

**听写默认使用 F9。** 在新版 Codex 的语音设置中配置听写快捷键后，NuPhyLab 自动读取绑定：配置了「按一下听写」时，按一次 F9 开始、再按一次结束；只有长按绑定时，按住说话、松开结束。NuPhyLab 不修改 Codex 的快捷键配置，听写是否录音及转写结果以 Codex 界面为准。

**批准／拒绝、Fast、直接分叉、按住说话、发送输入、技能直达、旋钮／摇杆控制仍未接入完整上下文接口。** 页面没有把这些功能标成可执行。听写和语音功能尚不具备 Micro 的完整录音状态灯语义。

任务状态来自本机索引、结构事件和任务写入进程的存活证据。当前进程持有任务且尚无结束事件时，长时间思考／工具执行不再因超过 15 秒而变灰；进程退出或旧进程遗留记录仍显示未确认。新版本未读存储可区分已读结果，暂时读取失败保留槽位，持续失败超过 30 秒后降为未知。任务状态持续刷新，只有 Codex 灯光模式向键盘输出任务颜色。部分桌面审批、语音状态及真实页面焦点无法从此只读来源完整取得。

详细读取范围、状态判定和兼容边界见 [Codex 集成说明](docs/CODEX_INTEGRATION.md)。灯效编辑和游戏不依赖 Codex 是否可用。

Claude Code 模式的实现范围、验证边界和换机注意事项见 [Claude Code 集成说明](docs/CLAUDE_CODE_INTEGRATION.md) 与 [合并后交接说明](docs/HANDOVER.md)。

## 查看 Codex 额度

「Codex」页会读取当前登录账户的真实额度窗口，包括剩余百分比和重置时间。额度来自 Codex 的官方 `account/rateLimits/read` 方法；不读取或复制登录令牌，不开始、续跑或审批任务。

## Claude Code 任务状态灯

「Claude Code」页把本机正在运行的 Claude Code 会话状态显示在键盘上。它与 Codex 模式并列，通过页面顶部的「任务来源应用」切换；同一时间只有一个来源占用任务键和命令键，另一个的按键绑定、状态颜色和灯光设置会原样保留。切换后导航栏名称、页面标题和提示文字都会跟着变。

### 首次接入（三步）

1. 打开 NuPhyLab，进入左侧「Claude Code」。
2. 点击「安装接入」→「安装」。NuPhyLab 会先备份 `~/.claude/settings.json`，再把自己的本地命令钩子合并进去。
3. 打开「Claude Code 模式」开关。连接 Air75 V3 后，F1–F6 就会显示会话状态。

安装是**可重复执行**的：再次点击不会产生重复条目，只会把条目更新到当前路径。配置里其他人的钩子、`model`、`theme`、MCP 设置等都不会被改动。

**已经打开的 Claude Code 会话**会在下一次活动（提交输入或调用工具）时开始上报，但不会补发之前的状态；想立刻看到状态就新开一个会话。

### 状态与颜色

| 状态 | 含义 | 触发事件 | 默认 RGB |
| --- | --- | --- | --- |
| 运行中 | 正在思考或执行工具 | `UserPromptSubmit` / `PreToolUse` / `PostToolUse` / `PermissionDenied` | `#304FFE` |
| 等待权限确认 | 有操作在等你批准 | `PermissionRequest`、`Notification(permission_prompt)` | `#FF6D00` |
| 本轮结束 · 等待输入 | 这一轮回答结束 | `Stop`、`Notification(idle_prompt)`、`SessionStart` | `#00FF4C` |
| 出错 | 本轮因错误中断 | `StopFailure`（携带错误类别） | `#FF0033` |
| 会话已结束 | 正常结束或进程已退出 | `SessionEnd`，或会话进程消失 | `#FFFFFF` |
| 状态未确认 | 证据不足 | 已识别会话但无事件，或长时间无事件且无法确认存活 | `#858582` |
| 未绑定 | 该灯位没有会话 | — | `#000000` |

两条明确的判定规则：

- **Claude 停止本轮响应不等于项目完成。** `Stop` 只会进入「本轮结束 · 等待输入」，不会显示成「已完成」。
- **单次工具失败不等于任务失败。** `PostToolUseFailure` 保持「运行中」，只累计失败次数并在会话说明里标注；只有 `StopFailure` 才是错误状态。

长时间运行不会被误判为断线：只要会话进程仍然存在（对照 Claude Code 自己维护的 `~/.claude/sessions/<pid>.json` 与进程启动时间），思考几十分钟也保持「运行中」。反之，进程消失才判定为结束。

### 多会话、灯光模式与按键

- **多任务灯位**：默认 F1–F6，每个灯位一个会话，互不覆盖。「会话来源」可选最近会话 / 仅进行中 / 需要关注优先 / 自定义会话；自定义模式下重复选择会交换位置。
- **单任务全键盘**：整把键盘用同一种颜色显示一个会话。只有一个会话时自动跟随；多个会话时可以指定一个，或选自动并用任务键切换。被指定的会话暂不可用时保持熄灯，不会自动改成别的会话。
- **状态灯**有独立的 0–100% 亮度、控制会话呼吸和命令键状态流光；亮灯时长与空闲休眠沿用「设备 → 灯光时间」的统一设置。
- **按键绑定**：任务键默认 F1–F6、命令键默认 F7–F12，点「更改」录入新键，重复占用会自动交换，设置保存在本机。游戏、按键触发和声音律动期间会接管灯光并暂停任务键；结束后自动恢复。

### 任务跳转与命令键

任务键按下会先选中该会话（控制会话呼吸），再执行「任务键跳转」里选择的动作：

| 动作 | 说明 |
| --- | --- |
| 打开对应会话（默认） | 用 Claude 桌面应用自己的深链 `claude://code/continue?session=local_<id>` 跳到该会话。 |
| 切换到 Claude 应用 | 用 `open -b com.anthropic.claudefordesktop` 激活 Claude 桌面应用，不定位具体会话。 |
| 打开项目文件夹 | 在访达中打开该会话的项目目录。 |
| 复制恢复命令 | 把 `cd '<项目目录>' && claude --resume <会话 ID>` 复制到剪贴板。 |
| 仅选中会话 | 只切换控制会话，不做任何跳转。 |

命令键（默认 F7–F12）可选：下一个需要关注的会话、下一个 / 上一个会话、切换到 Claude 应用、打开项目文件夹、复制恢复命令、切换灯光模式、唤醒状态灯、刷新会话状态、不执行。**全部在本机执行，不需要辅助功能权限，也不会向 Claude Code 发送任何按键或输入。**

**「打开对应会话」怎么定位到具体会话：** 深链里的 `local_<id>` 是 **Claude 桌面应用自己的会话 ID**，不是 Claude Code 的 `session_id`。两者的对应关系来自桌面应用自己的记录 `~/Library/Application Support/Claude/claude-code-sessions/**/local_<uuid>.json`，其中 `sessionId` 是深链要的 ID、`cliSessionId` 是钩子报告的 ID。NuPhyLab 只读这两个字段，同一文件里的标题、首条消息和系统提示一律不读。链接格式取自已安装桌面应用自身的 URL 路由（它校验 `last` 或 `/^local_[A-Za-z0-9-]{1,64}$/`），用的是 macOS 公开的 URL scheme。

没有桌面记录的会话（例如在终端里直接运行 `claude` 启动的）**明确禁用**跳转并说明原因——拿 Claude Code 的 UUID 去拼链接会通过格式校验但找不到会话，结果是**静默新建一个会话**，所以不做这种猜测。可改用「打开项目文件夹」或「复制恢复命令」。

明确**不提供**并在界面上标注原因的功能：

- **批准 / 拒绝权限请求**：NuPhyLab 不会代替你做权限判断。
- **向会话发送输入 / 新建会话**：Claude Code 没有面向第三方应用的本机输入接口；向无法确认的终端窗口发送按键不可靠，因此不做。
- **定位终端会话窗口**：在终端里运行的会话无法可靠定位窗口，「切换到 Claude 应用」对这类会话会禁用并说明原因，可改用「打开项目文件夹」或「复制恢复命令」。

### 账户额度

Claude Code 页的「账户额度」显示**暂不支持读取**。Claude Code 没有提供给第三方应用读取订阅额度的本机接口，`/usage` 和 `/status` 是交互式界面内的命令；Rate Limits API 面向 API Key 账户，也需要读取凭据。NuPhyLab 不会用 token 消耗、费用或推测值冒充剩余额度，也不会读取或复制登录凭据。请在 Claude Code 里用 `/usage` 或 `/status` 查看。

### 记录了什么、没记录什么

钩子只写入这些字段：会话 ID、项目目录、Claude Code 进程号、时间戳、事件名、工具名、通知类别、结构化原因码（如 `startup`、`clear`、`rate_limit`）和权限模式。

**不会**记录提示词、工具输入、工具输出、助手回复正文、对话记录路径内容或任何账号凭据。钩子脚本是本地命令，不联网、不调用模型；NuPhyLab 没运行时它只是把一行状态写进本机文件后立即退出。新增通信只发生在本机文件系统，不开放任何新端口。

### 怎么测试

不接键盘也能验证：安装接入后，用安装好的钩子脚本灌入事件，再看页面：

```sh
HOOK="$HOME/Library/Application Support/Air Studio/claude-hook/nuphylab-claude-hook.sh"
SPOOL="$HOME/Library/Application Support/Air Studio/claude-sessions"
echo '{"hook_event_name":"UserPromptSubmit","session_id":"demo-1","cwd":"'"$HOME"'"}' | "$HOOK" "$SPOOL"
```

真实验证：安装后在任意目录开一个 Claude Code 会话，随便让它执行一条命令，「Claude Code」页应立刻出现该会话并显示「运行中」。

自动测试见 `tests/claude-*.test.mjs`，运行 `npm test`。这些测试全部使用临时目录，**不会**改动你真实的 `~/.claude`。

### 移除接入

在「Claude Code → 查看接入 → 移除接入 → 确认移除」。NuPhyLab 只删除自己添加的条目（通过钩子脚本文件名识别），其他钩子、其他设置和文件顺序保持不变；条目被清空后不会留下空的 `hooks` 结构。同时删除自己的钩子脚本目录和会话状态文件，不会动 `~/.claude` 里的其他内容。移除前同样会备份原配置。

备份保存在 `~/.claude/nuphylab-backups/`，最多保留 10 份。

### 已知限制

- 钩子每次触发会启动一次 Node 解释器（约 40–60 毫秒），只在本机文件里追加一行，不阻塞 Claude Code，超过 1.2 秒读不到输入就自行退出并返回 `{}`，任何异常都不会改变权限判断。
- 事件字段以本机实际安装的 Claude Code 版本为准（本项目在 CLI 2.1.174 / 桌面应用 2.1.247 上实测）。不同版本字段名可能不同，代码同时兼容新旧两种写法；遇到无法识别的事件会忽略而不是猜测。
- `~/.claude/sessions/` 是 Claude Code 自己维护的本机会话记录，只读使用；如果某个版本不写这个目录，会退回进程号判断并放宽 60 秒宽限。
- 未接入前已经在运行的会话会显示「状态未确认」，直到它下一次活动。
- 会话跳转依赖 Claude 桌面应用的本机会话记录。该记录的位置和字段名不是公开接口，桌面应用升级后可能变化；读不到时跳转会自动变为不可用并说明原因，不会退化成静默新建会话。可用 `CLAUDE_DESKTOP_SUPPORT` 指定其他位置。
- 绑定普通按键（字母、数字等）时，该键在模式开启期间会被全局接管、无法正常输入；页面会明确警告，「会话与按键」右上角的「恢复默认按键」可一键还原 F1–F12。

## 后台播放、停止与退出

窗口默认内容区约为 **1100 × 700**（根据屏幕可见区域适配），可以拖动边缘自由调整，最小为 720 × 520。应用会记住窗口大小和位置；使用 **⌘0** 或「窗口 → 恢复默认窗口大小」可重置。页面在较窄时自动重排，并保留纵向滚动。

关闭编辑窗口后，菜单栏里的键盘图标仍会保留，普通灯效继续由本地服务播放；游戏会自动暂停，重新打开游戏页后手动继续。菜单栏提供：

- 「打开 NuPhyLab」：重新打开编辑窗口。
- 「暂停 / 继续」：暂停或继续当前播放。
- 「停止并恢复键盘灯效」：停止控制并恢复接管前的灯效配置。
- 「退出 NuPhyLab」：先执行恢复，再退出常驻程序。

应用第一次改变灯效前，会把原始状态备份到磁盘。恢复时读取键盘核对完整配置，确认后才删除备份。正常退出和进程 SIGTERM 的恢复路径已做真机验证。

拔掉数据线、Mac 休眠或强制结束进程可能中断通信。Mac 休眠期间不会继续发送动画；恢复连接后由服务重新检查设备。SIGKILL、系统崩溃或设备断电无法执行即时清理，原始备份会保留。重新打开软件后，应先在设备页恢复原灯效，再继续创作。不要在尚未恢复时直接删除备份文件。

NuPhyIO 与其他灯效程序不能和 NuPhyLab 同时操作同一个 HID 会话。如果需要使用官方配置器，先在 NuPhyLab 中停止并断开键盘。

## 本地文件

打包应用和默认源码服务使用同一个数据目录。更名为 NuPhyLab 后沿用原有目录，以保留已有作品与设置：

```text
~/Library/Application Support/Air Studio/
├── library.json             作品、动画、设置和各游戏最高纪录
├── original-lighting.json   接管前的灯效备份；恢复成功后移除
├── runtime.json             当前本机服务的端口、进程与会话信息
├── claude-hook/             Claude Code 钩子脚本（安装接入后生成，移除时删除）
└── claude-sessions/         Claude Code 会话状态记录，一个会话一个文件
```

`claude-sessions/` 只存放上面「记录了什么」列出的字段；超过 7 天未更新的文件会自动清理，移除接入时整目录删除。

备份作品可导出 JSON，也可以在退出应用后复制 `library.json`。`runtime.json` 含本次本机 API 会话 token，不需要作为作品备份分享。源码运行可通过 `AIR_STUDIO_DATA` 指定独立数据目录。

界面与服务通过随机本机端口通信，仅监听 `127.0.0.1`，API 使用本次运行的会话 token。作品没有云端同步功能。Codex 额度查询仍需要现有 Codex 账户连接其服务。Claude Code 接入完全在本机文件之间完成，不新增任何网络端口。

## 支持范围与键盘地图

当前适配对象是 **NuPhy Air75 V3 ANSI，有线连接**，USB 标识为 `19f5:1028`；已在 **1.0.16.6 和 1.0.23.6** 完成灯效真机验证，最新回归使用 Mac 档。程序会识别 Mac／Win 配置通道，检查设备接口、灯位及协议结构，不会自动刷固件。同一协议系列的新固件通过运行时检查后可使用；协议或设备布局发生变化仍需适配。Air75 V2、HE、ISO/JIS 和其他型号不能视为已经兼容。

需要区分两个数字：

- **83 个已映射的画布位置**：采用官方 ANSI 布局和原图位置校正，分布在六行，对应索引 0–82。第一排连续排列；索引 14 位于 `x=14, y=0`，界面键帽显示 Ins，硬件映射仍为 Insert。最右 `x=15, y=0` 按用户要求显示装饰 Del 键帽，替代原旋钮图示；此处不可绘制，不作为按键灯，也不消费 RGB 索引。
- **84 个主区 RGB 逻辑通道**：固件实际暴露索引 0–83，真机已验证所有 84 个通道都能写入并精确回读。索引 83 的物理位置尚未确认，因此没有在画布上编造一个键；它保留在 84 色数组中，默认黑色。

RGB 回读证明数据通道有效，不能替代逐个物理灯位的光学验证。不同公开键位表在少数位置有冲突，后续应在明确测量后更新地图。20 个侧灯条目另计，因此完整回读共有 104 个 RGB 条目。

## 从源码构建

需要 macOS、Xcode Command Line Tools（提供 Swift 编译器）、Node.js 22 或更新版本，以及 npm。在项目根目录运行：

```sh
npm run setup
npm run build
npm test
```

启动本机开发服务：

```sh
npm start
```

服务会输出本次 `127.0.0.1` 地址，可在浏览器中打开。键盘访问仍由原生 helper 完成，浏览器不需要 WebHID；源码模式不会提供 AppKit 菜单栏和宿主全局任务快捷键。不要和打包应用同时控制键盘。

打包原生应用：

```sh
npm run package
open "release/NuPhyLab.app"
```

`npm run package` 会重新构建 Swift helper、AppKit 宿主和前端，再把本机 Node 运行时、服务和 `hooks/` 复制到 `.app` 中，并使用 Apple 证书签名。仅有一个有效的 Apple Development / Developer ID Application 证书时自动选择；多个证书时用 `AIR_STUDIO_SIGN_IDENTITY` 指定证书名称或指纹。请持续使用同一个签名身份。运行中的应用不能被原地覆盖，请先退出或打包到临时目录后整体替换。请在与目标机器架构相符的 Mac 上构建。

本项目继续使用原有 `local.airstudio.desktop` 标识符与稳定的 Apple 签名身份。应用显示名称是 NuPhyLab；不要为改名或合并源码而更换标识符，以免影响已有系统授权。

没有 Apple 证书的开发机可显式指定本机自签名证书：

```sh
AIR_STUDIO_SIGN_IDENTITY="NuPhyLab Local Code Signing" npm run package
```

自动选择仍只接受 Apple Development / Developer ID Application。自签名仅供本机开发，授权是否可沿用还取决于证书信任和系统策略；正式更新应保持同一个签名身份。临时测试也可显式设置 `AIR_STUDIO_ALLOW_ADHOC=1`，但 ad-hoc 签名会随构建变化，可能导致原有权限记录失效，不能用它替换此开发机的稳定签名包。默认不会静默回退。

打包会检查 Node 是否只依赖系统动态库，避免将 Homebrew 外部依赖带给用户。当前开发机使用已验证的自包含运行时；需要获取运行时时使用 `npm run fetch-node`，下载官方文件并核对 SHA-256，保存在 `vendor/node-<arch>/`。该目录不进入源码包。

主要目录：

| 目录 | 用途 |
| --- | --- |
| `ui/` | React / TypeScript 可视化编辑器 |
| `server/` | 本机服务、播放引擎、作品存储及 Codex 读取 |
| `shared/` | ANSI 位置映射与共用颜色数据 |
| `native/HIDBridge.swift` | USB HID、备份恢复、权限及明确请求的快捷动作 |
| `native/AppHost.swift` | macOS 窗口、菜单栏、文件导入导出与任务快捷键 |
| `hooks/` | Claude Code 钩子脚本源文件，安装时复制到数据目录 |
| `scripts/package.mjs` | `.app` 组装和本机签名 |
| `tests/` | 不操作真实键盘的自动检查 |
| `docs/` | API、硬件及 Codex 集成说明 |

## 验证与排查

各版本的检查范围和结果以 [完整验证记录](docs/ACCEPTANCE.md) 与 [硬件验证报告](docs/HARDWARE_QA.md) 为准。已有的贪吃蛇真机记录不能替代打地鼠、记忆灯序或双人乒乓球的验收；新增游戏的实际检查结果应单独记录。其他 Mac、固件和布局不包含在原有本机验收范围内。

原生离线自检不会打开键盘：

```sh
bin/HIDBridge --self-test
```

完整 JSONL 契约、错误码语义和需要明确选择执行的真机复验方式见 [原生协议说明](native/PROTOCOL.md)。真实灯效复验会临时改变键盘灯光，请先停止主应用连接；日常使用无需重复运行它。

| 遇到的情况 | 处理方式 |
| --- | --- |
| 找不到键盘 | 确认数据线和有线模式，检查设备是否为 Air75 V3 ANSI，并关闭 NuPhyIO |
| 权限未允许 | 在设备页点击对应「允许」，到系统设置中开启后返回，页面会自动刷新；若深链未定位，请手动进入「隐私与安全性」。系统若明确要求重开应用，再按提示操作 |
| 界面提示存在待恢复备份 | 保持键盘连接，先执行恢复；不要用新灯效覆盖原备份 |
| 灯效通信超时 | 停止其他 HID 程序，重新连接数据线，再检查恢复状态 |
| Codex 状态为 `unknown` | 等待新的可识别事件，或刷新读取；它不等同于任务失败 |
| Claude Code 会话显示「状态未确认」 | 该会话在安装接入前就已启动；让它执行一步操作，或新开一个会话 |
| Claude Code 页显示「尚未接入」 | 在该页点「安装接入」；若提示无法读取配置，请先修正 `~/.claude/settings.json` 的 JSON 格式 |
| 安装后仍然没有任何会话 | 确认 `~/.claude/settings.json` 里 `disableAllHooks` 不是 `true`，页面会直接提示这一项 |
| 额度不可用 | 查看 Codex 账户登录和网络状态；不会用虚构百分比补足 |
| 作品库格式异常 | 原文件会保留，软件拒绝覆盖；先备份 `library.json` 再修复 |

## 按键触发图案

在「创作台 → 按键触发」中，点击触发按键旁的「更改」，按下并松开想使用的键，即可自动识别。点击「取消」或其他区域可保留原按键；Esc、Tab 本身也可以录入。设置次数和速度后启用；已经启用时，修改后点击「应用设置」。默认空格让新爱心闪烁3次，结束后继续熄灭等待；颜色支持连续色盘及每键独立绘制。触发配置与作品一起保存。全局监听保留正常输入；缺少系统权限时会明确显示窗口内监听。关闭后恢复原灯效。验证范围见 [触发验收记录](docs/TRIGGER_QA.md) 与 [按键录入验收记录](docs/TRIGGER_KEY_RECORDER_QA.md)。

### 系统已允许，但应用仍显示未允许

旧版使用 ad-hoc 签名，macOS 的授权条目绑定旧构建的内容哈希，更新后可能出现“系统开关开启、应用实际无权限”。现在改用稳定的 Apple 证书身份。旧条目需要在系统设置中移除，再添加当前的 NuPhyLab；输入监控与辅助功能各自保留独立授权。输入监控若提示退出并重新打开，请按提示操作。此修复不会写入 TCC 数据库、关闭系统保护或授予其他应用权限。
