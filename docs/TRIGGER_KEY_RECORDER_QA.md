# 按键录入验收 · 2026-09-11

触发键下拉框已替换成当前按键与「更改」按钮。点击后等待单个物理键，按下识别、松开确认；取消或点击外部保留原值。按物理键 code 匹配现有 74 键允许列表，拒绝修饰组合和不支持的键。录入时拦截当前窗口的默认按键行为，避免空格滚动、Tab 跳焦点及意外启动窗口触发。

## 验证结果

- `npm run build:ui`：TypeScript 与生产构建通过。
- `node --test tests/trigger.test.mjs tests/trigger-service.test.mjs`：13/13 通过。
- 隔离服务与 CUA 浏览器实操：K、空格、Enter、Tab、Esc、↑、Backspace、Del、F6、数字 4 均识别正确。
- Shift+K 不被接受；F13 显示暂不支持，随后仍可录入空格。
- 取消、点击其他字段、离开页面均保留原按键；断开设备后仍可录入。
- 用 Enter 激活「更改」后正常等待下一次按键，录入空格或 Enter 后不会重新打开录入状态。
- 录入过程中次数 5、周期 600 ms 保持不变；保存作品并重新打开后 K / 5 / 600 ms 全部保留。
- 窗口监听已启用时录入 K 不触发灯效；结束录入后点击键盘画布，再按 K，正常进入 5 次闪烁。
- 1280×720 与 720×520 界面检查通过；提示跨两列排版，小窗口无横向溢出。

这是前台按键录入控件更新，没有修改 USB 协议或全局监听权限。测试中的按键由 CUA 输入，不能等同于手指按实体键到灯光的整链路观察。LED 数量解析修复继续保留，见 [LED 数量验收](LED_COUNT_QA.md)。
