# Codex Micro 功能与灯光核查

核查日期：2026-09-10 至 09-11。对照对象：本机 Codex / ChatGPT 桌面版 **26.903.71938**、Work Louder Input 稳定版 **0.18.4**，以及当前 Air Studio 源码。

**结论：当前 Air Studio 的 Codex 页面只有部分任务灯与快捷入口，距离 Micro 的完整交互还有明显差距。多数缺项是软件没有实现，不能归因于 Air75 V3 不支持。** 灯效名称相同也不代表行为相同；当前程序的“彩虹、呼吸”等动画，不能替代 Micro 的任务、语音、选中状态与分区反馈。

这是一份版本限定的功能核查与后续验收基线，不是“已经补齐”的交付声明。本轮没有更换正在运行的 Air Studio，没有修改用户作品、键盘固件或 Codex 设置。没有 Micro 实物，因此 Micro 行为以官方文档和发行程序的静态实现交叉确认，未宣称做过 Micro 实机测试。

## 2026-09-11 实现更新

以下章节保留首次审计时的差距，**不是当前实现清单**。当前实现以 [集成说明](CODEX_INTEGRATION.md) 为准。

本次已统一数字 RGB，移除预览白色混合，接入本机未读新格式及任务进程存活证据，保留读取失败时的槽位，修复暂停动画导致任务灯停止更新。新增四种本机任务来源、控制任务呼吸、F7–F12 状态流光、独立亮度与自动息灯、六个可配置命令键和 23 个默认快捷入口。

真实 Codex 焦点、部分审批和语音状态，以及 Fast／直接分叉／发送输入／按住说话／技能／旋钮摇杆仍未接入。电脑操作工具拒绝访问 Codex，因此没有宣称直接点击 Micro 设置或验证过全部 Codex UI 动作。新 UI 与服务测试使用隔离数据，键盘 RGB 检查使用已连接的 Air75 V3。

## 一、灯光：原生状态显示

### 1.1 六个任务键

以下 RGB 来自本机官方实现 L1。它们是发送给 Micro 的数字值，不等于不同键帽、扩散材料下肉眼看到的绝对颜色。

| 状态 | Micro RGB | 行为 | 当前 Air Studio |
|---|---|---|---|
| 空闲 idle | `#FFFFFF` | 已分配任务、当前没有待关注状态 | 有近似状态，灯光引擎改成了暖灰 |
| 工作 working | `#304FFE` | 思考／处理任务 | 有轮询推断，颜色不同，长时间静默会变为未知 |
| 未读 unread | `#00FF4C` | 有未读结果 | 简化为“已完成”，语义和颜色均需校正 |
| 等待批准 awaiting-approval | `#FF6D00` | 有待处理批准请求 | 与“等待输入”合并，且部分桌面请求读不到 |
| 等待回答 awaiting-response | `#FF6D00` | 需要用户回答 | 与批准合并，未完整区分 |
| 错误 error | `#FF0033` | 任务发生错误 | 有近似状态，颜色不同 |
| 没有分配 off | `#000000` | 灭灯 | 空槽位已有 |
| 当前选中任务 | 保留该任务的状态色 | 任务键呼吸；其余任务键常亮 | 缺少真实选中状态和呼吸反馈 |

Micro 没有在这套枚举里定义灰色“未知”。Air Studio 需要保留未知状态，以诚实反映外部读取能力不足；不能为了模仿官方颜色，把未知伪装成工作中或空闲。

### 1.2 命令区、外围灯与临时反馈

| 触发条件 | 本机 Micro 实现 | 当前缺项 |
|---|---|---|
| 切换到一个任务 | 命令区短时用状态色点亮；对应的外围提示也会出现，选择提示约 **4 秒** | 没有选中反馈与计时恢复 |
| 选中任务正在工作 | 外围用蓝色 `snake` 流动；4 秒选择提示结束后仍可继续 | 没有任务驱动的流动区域 |
| 选中任务非工作状态 | 选择提示结束后，命令区／普通外围提示熄灭；任务键仍保留状态 | 没有独立区域和回退规则 |
| 开始录音 | 外围海绿色 `#2E8B57` 流动 | 没有真实录音状态灯 |
| 转写处理 | 外围白色流动 | 没有转写处理中状态灯 |
| 转写就绪 | 外围白色常亮 | 没有“可发送”反馈 |
| 输入区控制菜单打开 | 旋钮旁任务键临时红色，按该键取消；实现还包含外围流动反馈 | 没有菜单反馈与按键临时接管 |
| 首次引导 | 六任务键演示状态变化，演示结束恢复实时任务状态 | 没有明确隔离的演示模式 |
| 内置小游戏 | 进入专用反馈层，部分游戏使用任务键作为操作，外围可出现红色流动 | Air 的灯光贪食蛇是独立功能，不等同于这个反馈层 |

L1 中任务键呼吸与外围流动都向固件发送 `speed = 0.4`。这是固件的归一化参数，**不能直接说成每秒 0.4 次或 2.5 秒一周期**。同样，Air 上的软件动画要以自己的时间单位明确描述，不能机械照搬该数值。

### 1.3 亮度、息灯、恢复

| 功能 | Micro | Air Studio |
|---|---|---|
| 亮度 | 0–100%，官方默认 100% | 已有全局亮度，默认 70% |
| 自动息灯 | 关闭／30 秒／1 分钟／3 分钟／10 分钟／30 分钟／1 小时；默认 3 分钟 | 缺少 |
| 息灯后唤醒 | 使用设备，或任务键状态发生变化 | 缺少 |
| 选中反馈恢复 | 临时提示结束后回到原本状态 | 缺少 |
| 连接异常 | 重连、输入与灯光控制可用性分开报告 | Air 有自己的重连和恢复；尚未覆盖全部 Micro 状态层 |
| 电池状态 | 设备有上报时显示 | 本项目 USB 灯控不以电池显示为目标，未实现同等入口 |

## 二、灯光：Input 的六种显示预设

**Input 的灯效预设，与 Codex 的任务状态显示是两个系统。** 以下是 L2 中实际用于下拉列表的全部六项，包含“关闭”。不是从宣传图猜出来的名称。

| 灯效 | 含义 | 可调整参数 | 当前 Air Studio |
|---|---|---|---|
| off | 关闭该区域 | 无 | 可把主灯涂黑；没有统一分区预设入口 |
| solid | 常亮 | 亮度、颜色 | 主灯可实现，没有完整分区配置 |
| snake | 流动光段 | 亮度、速度、颜色 | 缺少等价预设；“平移图案”与游戏蛇不等同于它 |
| rainbow | 彩虹 | 亮度、速度、Magic | 有自有彩虹算法，没有分区和 Magic |
| breath | 呼吸 | 亮度、速度、Magic、颜色 | 有自有呼吸算法，参数和分区不齐 |
| gradient | 渐变 | 亮度、Magic、颜色；该界面禁用速度 | 可手绘颜色，但没有该参数化预设 |

亮度、速度、Magic 在 Input 中均以 0–100 控件呈现；Magic 是依效果而异的固件参数。已确认控件的启用条件，**尚未确认每种效果的固件数学公式**，不能武断命名为“尾迹长度”或“饱和度”。

Input 还提供：

- **Backlight / Underglow 独立配置**：两区各自选择灯效、亮度与适用参数。
- **每层保存灯光**：跟随该层的映射配置；可将某一区域设置应用到全部层。
- **即时预览**：参数编辑会发送灯光预览。
- **颜色输入**：色相控件和十六进制颜色值。
- **默认组合**：Micro 背光为白色常亮，外围为彩虹。默认亮度均 100%；外围速度 55%、Magic 100%。这是 Input 的默认值，不是 Codex 接管后一直保持的效果。

在官方 Codex 附带的设备 SDK 中还发现第七个底层枚举 `shallowBreath`（浅呼吸）。**它没有出现在本次核对的 Input 六项灯效菜单，也不是 Codex 设置中可选的第七款预设。** 可以作为 Air 的额外效果，但应标注为扩展。

## 三、任务键与任务组织

| 功能 | Micro 行为 | 当前 Air Studio / 补齐条件 |
|---|---|---|
| 六任务槽位 | 与任务状态、操作绑定 | 有 F1–F6 灯位与任务下拉选择 |
| 最近任务模式 | 最近的已固定和未固定任务 | 部分：Air 只读取本机最近任务，语义不完全相同 |
| 固定任务模式 | 根据应用固定顺序选择，含固定项目中的任务 | 缺少；需要完整排序来源 |
| 优先模式 | 等待处理、未读、正在进行优先 | 缺少；需要先改善状态来源 |
| 自定义模式 | 每槽可指定任务、命令、键帽动作或已启用技能 | 只有指定任务，缺少其他动作类型 |
| 空自定义槽位 | 开新任务，并在任务建立后自动绑定该槽 | 缺少 |
| 单击任务键 | 切换任务，默认不抢前台 | 当前 deep link 会打开任务，缺少后台切换保证 |
| 双击任务键 | 350 毫秒内双击切换并激活应用 | 缺少双击语义 |
| 单击前台开关 | 用户可改为单击就激活应用 | 缺少 |
| 跨来源任务 | 官方实现纳入本机、远程／云端等可用任务 | 当前仅本机 SQLite 索引 |
| 选中状态 | 与应用真实当前任务同步 | 缺少；不能把“最近一次在 Air 点击”当成真实当前任务 |
| 实际按键入口 | Micro 的任务键直接触发动作 | Air 原生入口目前是 Ctrl+Option+1–6；F1–F6 灯位并不等于 F1–F6 已被重映射 |

## 四、命令键：默认六键只是起点

| 默认键帽 | 默认动作 | 当前 Air Studio |
|---|---|---|
| FAST | 切换 Fast 模式 | 缺少 |
| APPR | 批准当前等待中的请求 | 未接入；必须定位真实请求 |
| REJ | 拒绝当前等待中的请求 | 未接入；必须定位真实请求 |
| SPLIT | 从当前任务分叉继续 | 缺少 |
| MIC | 按住录音、松开结束；支持免手持 | 只有听写／语音快捷入口，不具备等价按压交互 |
| CODEX | 发送输入框内容 | 缺少 |

本机版本的键帽目录有 **39 个软件条目**，包括单宽／双宽麦克风和空白项；这个数不等于包装里的物理键帽数量。可绑定动作覆盖终端、浏览器、复制对话、归档、新建、固定、评审、环境命令、Git、PR、附件、设置、侧任务、定时任务和推理强度等。完整的逐键默认映射见 [命令与键帽清单](CODEX_MICRO_COMMANDS.md)。例如：`BUG` 是反馈入口，不是自动修 Bug；`PARTY` 打开侧任务，不是彩灯派对；`DWN` 复制对话 Markdown，不是下载文件。

进一步按官方 Micro 的命令目录过滤规则，静态整理出本版本 **134 个候选命令**。其中 Air 当前提供 11 个默认快捷入口，2 个批准／拒绝入口禁用，其余 121 个未接入。这不是功能完成率：直接打开任务还另有 deep link 入口，一个动作也可能需要多项状态与手势配合。候选目录**不是在任何页面都可执行的 134 个按钮**：模式、项目、当前请求、模型、账号能力、技能启用情况和功能开关仍会限制执行。清单保留默认键位与限制；没有把缺省快捷键的命令臆造为某个组合键。

还缺少的配置行为：命令／技能搜索、单键重新分配、重复键帽交换位置、麦克风宽键拆分、整套布局重置。Micro 的布局重置保留任务来源模式和自定义任务绑定；Air 后续重置也应明确范围。

| 功能 | Micro | Air Studio |

## 七、Air75 V3 的实际边界

依据项目已完成的 USB 协议测试，主键区有 83 个已定位的可控键灯；写入协议中的第 84 个槽位未对应实体键，继续保持黑色。旋钮位置没有已验证的独立键灯。两侧共 20 灯，目前可靠控制的是侧灯整区。

因此应区分三类事情：

1. **可以直接补的软件缺项**：主键区流动／渐变预设、独立的任务灯显示方案、选中呼吸的渲染器、亮度与息灯配置、状态图例、映射配置界面、预览与作品保存。渲染器能做不代表已经拿到真实状态，演示必须显式标注。
2. **必须先打通状态／控制来源**：真实选中任务、长期运行状态、全部批准卡片、录音／转写状态、后台切换、Fast／Plan／推理强度与输入区控制。当前只读索引不是官方 Micro 的实时事件通道。没有默认快捷键也不代表硬件不支持，但必须验证自定义快捷键或其他受支持入口，不能靠猜测或模拟状态交付。
3. **当前协议不能保证等价**：左右侧灯分别显示、侧灯逐颗进度条、环形灯的空间流动、Micro 模拟摇杆和触摸条。可将流动效果放到主键区外围一圈，侧灯做整区颜色／明暗提示；这是 Air 适配方案，不是原样复制。

Codex 额度侧灯是用户提出的 **Air 扩展功能**，本次没有找到 Micro 原生提供额度进度灯的证据。爱心绘制、逐键异色、逐帧平移循环、整把键盘灯光贪食蛇也应按 Air 的原始需求独立验收，不能混入“Micro 自带功能”数量。

## 八、补齐顺序与验收标准

### P0：先把状态与能力定义纠正

- 统一官方数字状态色；UI 保持用户选择的克制配色，设备状态色独立定义。
- 区分未读、待批准、待回答、未知；明确每个状态的证据来源。
- 把每项标记为已实现、部分实现、待接入或硬件替代，去掉“六个常亮灯就等价 Micro”的产品预期。
- 使用真实状态与动作回读验证。不能只因为函数返回成功就显示“已批准”或“正在录音”。

### P1：完整灯光系统

- 六种 Input 类预设与参数；任务键、主键区、侧灯分别配置。
- 当前任务呼吸、任务切换短时提示、工作流动、语音三阶段提示。
- 明确显示优先级：游戏独占 → 交互临时提示 → 任务状态 → 用户底图；侧灯的额度／任务／用户灯效必须有明确选择和恢复策略。此顺序是拟采用的 Air 设计，不冒充 Micro 官方规则。
- 自动息灯、输入／状态变化唤醒、断线和退出后的恢复。

### P2：完整控制与配置

- 四种任务排序来源、自定义动作／技能槽、单击／双击与前台策略。
- 默认六命令与全部候选命令的配置入口，明确按当前上下文筛选。
- Air 旋钮、四键方向替代、按住／双击语音；动作配置与灯光配置分开编辑。
- Profile 保存、导入导出、按应用选择；替代方案须写明与 Micro 的差异。

### P3：扩展玩法

- 用户的逐键爱心与动画编辑继续独立完善。
- 保持全键区 Snake 只有蛇和食物点亮、其余键灯与侧灯熄灭。
- 如加入其他游戏，区分屏幕游戏与键盘 LED 游戏，不将 Micro 彩蛋名称当作已完成的功能。

### 自行验证，不转交用户

后续每一项需要同时满足适用的证据：状态／手势的确定性测试，UI 实际交互，USB 写入与颜色回读，动画结束／切换／断线／重连／退出恢复。批准、拒绝和发送动作使用隔离测试上下文，不借用户正在进行的任务当测试对象。无法取得完整链路证据的功能保留明确的待接入状态，不算交付通过。

UI 继续维持紧凑窗口：一级仅保留创作、Codex 控制与设备；Codex 内分任务、按键、状态灯。高阶参数在选中具体灯效或动作后显示，避免把这份清单展开成一个拥挤的大页面。
