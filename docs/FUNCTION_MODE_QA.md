# Codex 模式与功能键修复 · 2026-09-16

现场通过 USB 读取 Air75 V3（固件 1.0.16.6）的实际基础层：实体 F1–F12 对应键盘 usage 104–115，即 F13–F24。旧版只有蓝牙适配包含完整扩展层；USB 的媒体键白名单只覆盖其中两个 usage。另一个问题是按键录入暂停快捷键后，服务也撤销了 F 区映射，导致录入器收不到标准 F 键。

本次调整：

- Codex 页统一使用「Codex 模式」开关。开启时启用按键适配与快捷控制；关闭时释放临时映射和原生快捷键，保留用户绑定。不改写键盘固件或全局功能键偏好。
- USB 按读回的实际物理键位兼容 F13–F24 扩展层。适配及回读时重新获取系统设备服务，避免跨重连沿用旧服务引用。既有自定义系统映射冲突仍明确拒绝覆盖。
- 录入期间单独持有临时会话，让全部 12 个 F 键可录入，同时禁用任务／命令执行。关闭模式也可修改绑定；保存、取消、失焦结束录入，失联会话的临时映射在 15 秒后撤销。会话标识避免旧窗口清理新窗口状态。
- 原生 F 区捕获统一处理系统保留键和 Fn 标记；与 Carbon、窗口事件共用按下／松开状态，避免一次按键执行两次。修改绑定会立即更新映射，不再等待轮询冷却时间。

验证结果：

1. 完整项目回归 190 项通过；Swift HID 自检 639 项通过；两个原生程序及界面生产构建通过。
2. 隔离测试覆盖全部 12 个 F 键的原生事件路由、按住去重、松开、模式关闭后的透传；模拟 Codex 服务覆盖命令分派、录入禁用、模式切换、游戏暂停、蓝牙兼容、原绑定保存和恢复。未向真实 Codex 发送动作或创建测试任务。
3. 正式签名应用连接实体 USB 键盘，系统属性回读确认 12 对扩展层映射全部生效。关闭模式后原生注册清空，所有相关设备服务恢复原先空映射，恢复记录清除。
4. 原生录入窗口通过工具发送 F1、F11，松开即保存；关闭模式与开启模式分别验证，未触发 Codex 命令（事件记录保持空）。这是原生输入路径验证，不代替实体开关逐键按压测试。
5. 恢复测试中暂改的任务绑定后，用户所有设置及作品与验证前逐项一致。正式应用退出 status=0 / signaled=false，无遗留子进程、按键或灯光恢复记录，系统映射再次确认为原值。

蓝牙路径经过模拟回归，本次现场连接为 USB；不声称本次逐键复测了蓝牙实体输入。用户仍可自由将任务或命令绑定到任意支持的按键。
