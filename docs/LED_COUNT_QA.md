# 灯位数量读取修复

验证日期：2026-09-11。设备：USB 有线 Air75 V3 ANSI `19f5:1028`，官方固件 `1.0.16.6`。

## 原因和修复

现场复现了 `Expected 104 LEDs; the device reported 32872`。A1 确认当前会话 XOR 密钥为 `0x80`。D1 实际只返回一字节灯位数量，后续字节为未加密填充；旧实现按两字节整数读取，把填充零 XOR 为 `0x80`，得到 `0x8068 = 32872`。会话密钥为零时，此错误不会显现。

两次抓取的 64 字节回复前 9 字节如下，其后均为 55 个零：

| 请求 | 回复前 9 字节 | 解释 |
| --- | --- | --- |
| 旧 D1 长度 2 | `aa d1 00 ea 82 80 80 80 e8` | 错把后面的填充零当数量高字节 |
| 修复 D1 长度 1 | `aa d1 00 e9 81 80 80 80 e8` | 只解码 `e8 XOR 80 = 68`，正确得到 104 |

修复统一使用一字节请求和专用 D1 解码器。没有屏蔽高位或强制把异常值替换为 104；真实数量不符、错误校验和及过期路由仍会被拒绝。全程未发送 EE、未改会话密钥、键位或固件。

## 已通过验证

- 原生自检 559 项：包含现场回复、全部 256 个密钥与两种路由格式、错误数量、损坏校验和、旧两字节回复拒绝，以及旧算法产生 32872 的复现。
- 服务测试 107 / 107 通过。
- `npm run build:native` 编译通过。
- 真机先精确恢复之前保留的灯效备份，再连续断开/连接 10 次；每次得到 104，17 字节灯效配置保持一致。
- 临时发送一帧低亮度颜色，D2 回读全部 104 个条目；前 84 个主区 RGB 与发送值逐个一致，未定位的索引 83 保持黑色。
- 结束后精确恢复原始 17 字节配置，helper 正常退出。

真机结果见 [led-count-qa-results.json](led-count-qa-results.json)。可以关闭 Air Studio 后显式运行：

```sh
node scripts/qa-led-count.mjs --run "$HOME/Library/Application Support/Air Studio/original-lighting.json"
```

该脚本会恢复所指定的待恢复备份、临时改变灯效并最终恢复。测试没有切换真实会话密钥；所有其他密钥组合在原生自检中验证。
